## Рекомендация
**Классический путь KenshiLib + VS2010 v100** — единственный проверенный: на нём живут RE_Kenshi и все плагины сборки, есть примеры (`HelloWorld`, `WorldStates`, `KillButton`, `PluginExport/Import`).
- Ставит владелец вручную: VS2019+/2022 Community, компиляторы VC++ 2010 x64 (VS2010 SP1), Boost из репо.
- Дальше плагин собирается и проверяется скриптом.
- До установки всё, что можно, делаем на KenshiLua.
- C-API форк — наблюдать: когда появится готовый фасад с релизом, можно будет уйти от VS2010.

## Задачи для C++-плагина (по приоритету)
1. **Оценка силы противника перед боем** (сила отряда, снаряжение, мотив, голод) — решение «бежать / биться / обойти» (CORE.md §5). Данными и KenshiLua не делается: пороги бегства считают только численность (поток E).
2. **Состояние уникальных NPC и world states без загрузки зоны.** Перехват `WorldEventStateQuery::isTrue` (как в примере `WorldStates`) или прямая запись в реестр состояний. Тогда исход «лидер убит / пленён» применяется сразу, а не когда лидер окажется рядом с игроком.
3. **Надёжные приказы отрядам**: цели ActivePlatoon/Platoon (Tasker, `addGoal`), марш к точке, оборона базы игрока, совместный рейд. В Lua сейчас только `createRandomSquad` с угаданными аргументами (не проверено).
4. **Истощение руды** (поток F): override выхода `ProductionBuilding` и хранение остатка узла в сейве. В KenshiLua нет override-колбэка объёма.
5. **Экипировка по богатству** через `createItem`/`equipItem` с проверкой слотов и расы. В Lua сейчас вслепую, под pcall.
6. **Запуск кампаний и рейдов фракций** (FACTION_CAMPAIGN) по решению дирижёра — «рейд на слабого» и «захват города» как реальные армии, а не только хроника.
7. Хранение состояния дирижёра в сейве нативно (сейчас `data_string` ключ, не проверено).

## Что проверить в первом тесте KenshiLua (до решения о плагине)
- `FactionRelations:setRelation` меняет отношения (видно на экране фракций).
- `createRandomSquad(...)` с нашими аргументами создаёт отряд, и он идёт к цели.
- `createItem` + `Inventory:addItem/equipItem` надевают вещь на NPC.
- `setChainedMode` засчитывается миром как плен.
- `data_string` сохраняется в сейве.

Что не сработает — переходит в задачи 2–5.

## Компилятор MSVC v100 без IDE — разведка (2026-11-12, ничего не ставилось)
**Факт из исходников:** `tools\ref\KenshiLib\KenshiLib.vcxproj` собирается с `PlatformToolset = Windows7.1SDK`, а README RE_Kenshi прямо называет «WIn7.1 SDK» альтернативой VS2010. Значит, IDE VS2010 не обязательна: хватит **Windows SDK 7.1** (в нём компиляторы VC++ 2010, cl 16.00, x86/x64) + **MSBuild** из **VS Build Tools 2019/2022** (без IDE). Тулсет `Windows7.1SDK` подхватывается MSBuild-ом, если SDK 7.1 установлен.

Состояние этого ПК (проверено реестром и путями): Visual Studio / Build Tools — нет; `Microsoft SDKs\Windows\v7.1` — нет; `VC\bin\amd64\cl.exe` (VS10) — нет; .NET Framework 4.8.1; **установлен Microsoft Visual C++ 2010 x86 Redistributable 10.0.40219**.

| Шаг | Что | Подводные камни |
|---|---|---|
| 1 | VS Build Tools 2019/2022 (MSBuild + v142/v143, без IDE) | ставится официальным установщиком Microsoft (вне Steam) |
| 2 | Windows SDK 7.1 (`GRMSDKX_EN_DVD.iso`, x64), компоненты «Visual C++ Compilers» + «Windows Headers and Libraries» | **установщик падает, если стоит VC++ 2010 Redistributable новее 10.0.30319** — на этом ПК он стоит (10.0.40219): удалить redistributable x86/x64 перед установкой SDK и вернуть после. Установщик SDK 7.1 проверяет .NET 4 «старым способом» и на 4.8 иногда ругается — ставить с ISO, отключив пункт .NET Development, если нужно |
| 3 | «Microsoft Visual C++ 2010 SP1 Compiler Update for the Windows SDK 7.1» (KB2519277) | без него компиляторы x64 SDK 7.1 бывают сломаны после любых SP1-обновлений |
| 4 | Boost 1.60 заголовки — уже в репо KenshiLib; для плагинов ATL/MFC не нужны (нужны только для сборки самого RE_Kenshi) | — |
| 5 | Сборка без IDE: `msbuild KenshiLib.vcxproj /p:Configuration=Release /p:Platform=x64` (тулсет Windows7.1SDK), затем плагин так же | скриптом после установки |

**Можно ли автоматически?** **Нет.** (1) Все дистрибутивы — вне Steam, а правило: «ничего не скачивать вне Steam». (2) Нужны права администратора и удаление VC++ 2010 Redistributable (может задеть другие программы; ставится обратно руками). (3) SDK 7.1 снят с основного Download Center, официальная копия ISO — только в архивных ссылках Microsoft/Wayback; доступность проверять владельцу. Итог: ставит владелец вручную по таблице (≈30–40 минут), дальше сборка и проверка плагина — скриптом.

## Список задач плагина (обновлено после шага 1 офлайн-билда)
1. **Оценка силы до боя** (отряд, тир снаряжения, мотив, голод) → «бежать / биться / обойти» ещё до сближения. Сейчас KMM_Self решает только в бою и только по надетым вещам ближайшего бойца.
2. **Настоящая сдача** (бросить оружие, перестать драться, плен по желанию игрока). Сейчас «сдача» = разбегаются (`runAway`); нокаут-режим экспериментальный.
3. **World states без загрузки зоны** (`WorldEventStateQuery::isTrue`): смерть/плен лидера и смена владельца города применяются сразу, а не при визите.
4. **Приказы отрядам**: колонны идут на конкретный город и штурмуют; защита базы игрока; совместный рейд по цели игрока. Сейчас — `createRandomSquad` с целью-городом/персонажем, поведение движка не гарантировано.
5. **Истощение руды через override выхода** `ProductionBuilding` (если `_resourceMiningLevel` движок пересчитывает) и хранение остатка узла в сейве, а не в файле.
6. **Переплавка у игрока** (сломанное снаряжение → металл): нет подходящего рецепта/хука в данных и Lua; в дирижёре переплавка абстрактная.
7. **Цены**: прямое управление ценой товара у торговца (сейчас `priceMultWhenITrade` отряда — эффект не проверен).
8. **Кампании фракций** (FACTION_CAMPAIGN) по решению дирижёра — реальные армии вместо следов рядом с игроком.
