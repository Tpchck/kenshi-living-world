# PLUGIN — KMM_Native v1 (RE_Kenshi, KenshiLib, 2026-11-12)

Мод build\KMM_Native: KMM_Native.dll + RE_Kenshi.json + kmm_native.json + scripts\init\KMM_Native.lua + пустой KMM_Native.mod. Исходники tools\cpp\kmm_native (src, third_party\KenshiLua.h, build.bat). Собирается Windows SDK 7.1 / VC++ 2010 SP1 x64, без Boost (src\kenshi_decl.h объявляет только нужные экспорты KenshiLib; build_verify.bat сверяет их с настоящими заголовками через Boost 1.60 и проверяет offsetof(GameData, stringID)==0x58).

## Что делает v1
- Хук WorldEventStateQuery::isTrue (RVA 0x9A6650) и WorldEventStateQuery::getFromData (RVA 0x9A7DC0) через KenshiLib::AddHook. getFromData строит карту «указатель запроса -> stringID записи WORLD_EVENT_STATE» (сам запрос gamedata не хранит). isTrue: если переопределений нет (счётчик 0), сразу возврат оригинала; иначе под shared-lock ищет указатель, при совпадении возвращает true/false. Хук не трогает Lua и не аллоцирует на горячем пути.
- Lua-модуль kmm_native (require или package.loadlib("KMM_Native.dll","luaopen_kmm_native")): ws_set(sid, bool), ws_clear(sid), ws_clear_all(), ws_get(sid) -> true/false/nil, ws_hook_active(), ws_stats() {hooked, get_hook, queries_mapped, overrides, hits, unmapped_calls}, version().
- Адаптер _G.KMM_Native: те же функции (stats вместо ws_stats), поле available (лениво), всё в pcall, при первой ошибке адаптер отключается, нет модуля — тихие no-op.
- Безопасность: kmm_native.json {"enabled","ws_hook","game_version":"1.0.65"}; нет файла или enabled!=true — ничего не хукается. Проверки: версия игры через KenshiLib::GetKenshiVersion (только 1.0.65, платформа не UNKNOWN), KenshiLua.dll загружен и ABI поддержан, AddHook вернул SUCCESS. Любая ошибка — лог в RE_Kenshi-лог (ErrorLog/DebugLog, префикс KMM_Native) и тихий отказ. Все точки входа обёрнуты try/catch; чтение stringID через SEH.
- Переопределения живут в памяти и не пишутся в сейв: дирижёр применяет их заново после загрузки (ws_clear_all, затем ws_set по своему состоянию).
- Офлайн-карта rules\ws_town_map.json (tools\cpp\ws_town_map.py): базовый город -> override-города (новый владелец, AND-условия world state, want 1/0, цепочки), by_state (какие города включает состояние), states (что проверяет: NPC жив/мёртв/в плену, город цел). Смена владельца T на F: найти override с faction==F, выставить ws_set(sid, want) для его world_states; для цепочки (depth>0) ещё chain_states.

## Порядок загрузки (правка не применена)
Плагины RE_Kenshi грузятся в порядке модов; KenshiLua (#51) в основе стоит раньше. rules\load_order.json: добавить "KMM_Native" в список "kmm" (например после KMM_Elite, до KMM_Stock), иначе mods_cfg.py мод не включит. Дирижёр обращается к KMM_Native лениво, порядок Lua-файлов не критичен.

## Не проверено в игре
- Вызывается ли isTrue не inlined из WorldEventStateQueryList::isTrue (0x69DC70); счётчик ws_stats().hits после ws_set покажет это.
- Были ли запросы созданы до установки хука getFromData (RE_Kenshi грузит плагины после LoadMods): ws_stats().unmapped_calls > 0 при активных override означает, что часть запросов не сопоставлена; тогда v2 читает статическую карту WorldEventStateQuery::statesData (RVA 0x2094420).
- Работает ли package.loadlib в песочнице KenshiLua (запасной путь регистрации модуля).
- GetKenshiVersion().GetVersion() под RE_Kenshi (откат на 1.0.65) должен вернуть "1.0.65"; если нет, поправить game_version в kmm_native.json.

### П.1 Состояние уникального NPC: НЕ реализовано (unique_set / unique_get в модуле нет)
Найдено в заголовках KenshiLib (1.0.65): FactionUniqueSquadManager (появление/респавн уникальных ОТРЯДОВ фракции, не состояний NPC; endOfUniqueSquad 0x2DE500; ProsperityManager::notifySpecialNPCDead(GameData*) 0x7BF380 — уведомление для процветания, не запись состояния); WorldEventStateQuery::uniqueNPCsAre / uniqueNPCsAreNot (+0x0 / +0x40, GameData* -> DEAD/ALIVE/IMPRISONED) — это ТРЕБУЕМЫЕ условия запроса, не фактическое состояние; Platoon::isDead (+0x1F0), imprisoned (+0x1F1), Platoon::declareDead 0x795E30, undeclareDead 0x7904D0, Character::declareDead 0x7A4FA0, ActivePlatoon::clearAllTheUniqueNPCStates 0x4FEFE0, _checkForUniqueCharactersOnUnload 0x9A6970, Character::uniqueStateUpdate 0x5CECF0, GameWorld::deathParade (+0x708, только загруженные Character). Чего нет: поля или структуры с реестром «GameData уникального NPC -> фактическое состояние» и функции «пометить уникального NPC мёртвым/пленённым без загрузки». Откуда WorldEventStateQuery::isTrue (0x9A6650) берёт фактическое состояние, по заголовкам не видно; выяснить можно только дизассемблированием isTrue. Запись Platoon::isDead/imprisoned в выгруженный платун возможна (Lua тоже: Platoon.imprisoned RW), но неизвестно, читает ли isTrue эти поля, и платун лидера пришлось бы искать перебором Faction::unloadedPlatoons по Platoon::squadleader; запись по смещениям наугад не делали. Решение: остановились. Следующий шаг (нужен дизассемблер): разобрать 0x9A6650 и 0x9A6970, найти структуру, из которой isTrue читает состояние уникального NPC, и писать только через найденный setter (кандидат — Platoon::declareDead 0x795E30). Пока связка «смена владельца -> вариант города» (LINKN) остаётся спящей.

### П.2 getFactionForce: реализовано (только чтение)
Lua: kmm_native.faction_force(fid), адаптер KMM_Native.getFactionForce(fid) -> {squads, chars, active_squads, active_chars, unloaded_squads, unloaded_chars, dead_squads, imprisoned_squads} или nil. Путь: ou (GameWorld, экспорт ?ou@@3PEAVGameWorld@@EA) -> factionMgr (+0x4A8) -> FactionManager::getFactionByStringID (RVA 0x2E7570, экспорт есть) -> Faction::activePlatoons / unloadedPlatoons (списки платунов; зона не грузится, игровые функции обхода не вызываются) -> по каждому Platoon: isDead (не считается, идёт в dead_squads), imprisoned, _characterCountCurrent. avg_tier не даётся: тир живёт в CharStats загруженных персонажей, у выгруженных платунов его в заголовках нет. Риск: чтение из Lua-потока, а списки платунов меняет поточный апдейт фракций (updateUnloadedPlatoons, periodicUpdateThreaded); блокировки игры нет, поэтому возможны устаревшие или несогласованные числа (SEH гасит падение, но не гонку); вызывать раз в игровой день. Платун на границе загрузки может попасть в оба списка, итог squads/chars считать оценкой.

### П.3 orderSquad: только исследование, не реализовано
Подтверждённого шаблона вызова нет: в KenshiLib_Examples (CharacterHighlight, Dialogue, HelloWorld, KillButton, WorldStates) приказы не отдаются; в BindingsReference KenshiLua только сигнатуры, примеров нет; в Lua-скриптах Workshop addOrder/addGoal не встречаются. Что есть: Character::addOrder(Building*, TaskType, RootObject*, shift, clear, Vector3) 0x5D1950 (путь приказов игрока), Character::addJob 0x5C8620, Character::addGoal(TaskType, RootObjectBase*) 0x5C88A0; AITaskSystem::addOrder(TaskType, hand, Vector3, clearOld, shift) 0x507C00, addJob 0x507F50, addGoal(Tasker*) 0x5071D0, removeGoal 0x506C10; ActivePlatoon::currentGoal (Tasker*, +0xC0, RW в Lua); TaskType: MOVE_CUS_ORDERED, ATTACK_ENEMIES, ATTACK_TOWN, PATROL, FOLLOW_PLAYER_ORDER, CHOOSE_ENEMY_AND_ATTACK и др. План: (1) только для ЗАГРУЖЕННОГО ActivePlatoon: лидер (getSquadLeader 0x791930) и AITaskSystem::addOrder (через getTaskSystem) с ATTACK_TOWN (цель — hand города) или MOVE_CUS_ORDERED + Vector3, clearOld=false, shift=false; (2) сначала проверить из Lua (Character:getTaskSystem():addOrder) на одном тестовом отряде в игре и только при успехе оборачивать нативно; (3) для выгруженных платунов этим путём приказ невозможен (AI-задачи живут в ActivePlatoon/Blackboard, выгруженное поведение задаёт UnloadedPlatoonJob через Campaign и FactionWarMgr::getMyUnloadedAI 0x9C3310) — для них проверять FactionWarMgr::triggerCampaign 0x9C8080 из Lua, как записано в REV2 п.5. Риск: неверный TaskType или цель без нужных данных подвешивает ИИ отряда; вызов не из игрового потока — гонка с апдейтом ИИ. Адаптер: KMM_Native.orderSquad(...) всегда false.
