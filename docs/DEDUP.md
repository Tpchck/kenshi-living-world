## 2. Дубликаты предметов: что вредит

Клоны почти целиком происходят из одного мода Animation - Collection Pack (ACP). Авторы раздают одну вещь под десятками имён. Примеры групп клонов: 132 шлема самураев, 129 самурайских брони, 128 Holy Chest Plate (Black/Blue/Green...), 38 Cargopants [padded] (цвета), 27 Samurai Helmet A (colored)/[alt]. Проверено вручную на группе Samurai Armour: различаются только имя и описание.

Вредит:
- Пулы гардероба (KMM_Wardrobe): 2976 клонов брони размывают выбор. Шанс предмета в пуле определяется числом записей, поэтому группа из 129 клонов весит как 129 разных вещей. Самый ощутимый вред.
- Лавки и vendor lists: клоны засоряют ассортимент однотипными позициями. Умеренный вред.
- Чертежи и крафт: ярлыки крафта на клоны плодят строки в меню. Малый вред (RESEARCH-дубликаты отдельно не считались).
- Подбор лута в Economy по пулам: умеренный.

Безвредно:
- Клоны ITEM (205): записки, книги, письма на общем меше (item_parchment 78 штук, item_book 34 и более) — разный сюжетный текст на общем меше.
- Визуал совпадает с ванильным, а статы другие (3311 из 3482): это варианты, а не дубли.
- Совпадение имён с ванильными (23: Ninja Zukin, Severed Cannibal * и т.д.): смотреть вручную, обычно замена намеренная.

## 4. Кандидаты на слияние

Критерий: из ресурсов только .mod/.info/.img/превью, нет dll/json/lua, ни один мод не указывает на него в dependencies/references, не KMM_, не пустой разделитель. Итого 166, из них 155 малых (менее 500 записей).

Экономия: слотов mods.cfg минус 154 из 785 (около 20%). Объём данных всего 1.98 МБ из 130 МБ, то есть выигрыш не в объёме, а в накладных расходах на мод (открытие файла, merge-блок, зависимости). Оценка порядка секунд при старте, не измерено. Отдельно 50 пустых разделителей автора можно убрать из mods.cfg (риск нулевой, польза косметическая).

Риски:
1. Порядок перекрытия: Merged стоит на месте последнего участника. У 69 из 155 есть поздняя правка тех же полей другим модом; их либо делить на сегменты (несколько KMM_Merged_N), либо не включать. 86 безопасны сразу. Оценка консервативная: учитывались все поздние моды, не только между участниками.
2. Заморозка обновлений Steam: копия не обновляется. Лечится манифестом md5 исходников (rules\merged_manifest.json): при расхождении генератор предупреждает и пересобирает.
3. Удаления INT_MAX: у кандидатов их нет, но генератор обязан переносить их как есть.
4. Относительные пути ресурсов: у отобранных ресурсов нет; 123 мода с ресурсами не включать.
5. Зависимости: у 59 кандидатов есть зависимости помимо ядра; Merged получает их объединение и стоит после всех.
6. Сейвы: stringID остаются прежними (kmod их не переименовывает), но список модов в сейве меняется. Для идущей кампании это главный риск: делать до нового старта или проверить на тестовом сейве.
7. Заголовок: merge-блок, last_id и save_count пересобираются; round-trip обязателен.

Безопасный вариант, KMM_Merged:
- генератор читает список rules\merge_list.json, берёт исходники в порядке mods.cfg;
- записи складываются последовательно с сохранением change-флагов и удалений (без свёртки в один слой);
- dependencies и references объединяются (без самих участников);
- проверка round-trip: kmod.load_chain для цепочки с исходниками и цепочки с Merged должны дать одинаковые sid, поля и ссылки; расхождение — сборка падает;
- mods_cfg.py выключает исходники только после успешной проверки, Merged ставит на позицию последнего участника, проверка зависимостей «выше» остаётся;
- начинать с 86 безопасных, остальные добавлять порциями.

## 5. Как решать без правки чужих модов

- Канонический представитель группы: для каждой из 806 групп клонов оставить одну запись (с самым чистым именем, без цвета в скобках), остальные (2976 ARMOUR + 205 ITEM) занести в `data\catalog_excluded.json` — механизм «вещи вне пулов» уже существует (его читают tools\catalog.py и поток ELITE). Записи в игре остаются (сейвы, лут NPC, ссылки), вред исчезает только в наших пулах.
- Список представителей строить скриптом по сигнатуре (строки + числа + ссылки) и класть в rules\dedup_canonical.json, чтобы обновление ACP не требовало ручной работы.
- Vendor lists: не добавлять исключённые sid в торговцев потока Economy; чужие списки не править.
- Полностью дублирующий мод отключать через rules\excluded_mods.json (как Deathstroke), только после проверки: нет новых записей, никто не ссылается, правки совпадают с победителем.
- Спорные поля чинить нашим потоком KMM_* (он грузится последним и по правилам владения полей побеждает).

## 6. Действия по приоритету (польза / риск / трудозатраты)

1. Исключить клоны ACP из пулов гардероба и лавок, канонический представитель на группу. Польза высокая, риск низкий, S–M.
2. Отчёт dedup в рантайм-проверки сборки (числа групп и исключённых, tools\dedup_report.py). Польза средняя, риск нулевой, S.
3. Отключить явные полные дубли: Better Storage System - Upgradeable Tiers, SCAR's pathfinding fix, две из трёх версий Yet More Idle Animations, один из пары Sharper Blunts/Slightly Adjusted Blunt Weapons. Польза малая–средняя, риск низкий после проверки на новые записи, S.
4. Проверить на новые записи 13 «мёртвых» модов из раздела 3 и отключить пустые. Польза малая, риск средний (потеря контента), S–M.
5. KMM_Merged из 86 безопасных малых модов с round-trip-проверкой: минус 85 слотов. Польза средняя, риск средний (сейвы, заморозка обновлений), M–L. После п.1, на тестовом сейве; остальные 69 вторым этапом.
6. Убрать 50 пустых разделителей из mods.cfg. Польза малая, риск малый, S.
7. Слияние 123 модов с ресурсами и 52 с dll/json/lua не делать.

Начать с п.1, затем п.3, затем прототип п.5 на 10–20 модах без зависимостей.

## 7. Ограничения анализа
- Клоны определяются по полям значений и ссылкам; различие только внутри .mesh/.dds не видно, кроме имени файла в полях.
- Конфликты считаются по записям, которые мод изменяет; повторное определение того же sid вторым модом учтено как изменение.
- Отдельного типа BLUEPRINT в данных нет, RESEARCH-дубликаты не считались.
- Время загрузки не измерялось.
