# RUMORS — поток B: хроника → игрок через KenshiLua (v0, 2026-11-11)
Мод: `build\KMM_Rumors\` (`KMM_Rumors.mod` — пустой, для лаунчера; логика — `scripts\init\KMM_Rumors.lua`). Отдельного rules-файла нет: параметры — таблица `CFG` в начале Lua-файла.

## Что делает прототип
1. Каждые `CHECK_INTERVAL_SEC` реальных секунд (тик `GameWorld::charsUpdate`) перечитывает `C:\KenshiModMap\logs\chronicle.log` (контракт потока A, TSV, 11 полей), если файл изменился.
2. Если персонаж игрока находится в городе (`getCurrentTownLocation()`), а рядом, ближе `TALK_RADIUS`, есть NPC, выбирает рассказчика: предпочитает бармена, потом торговца, потом стражу (по имени шаблона `data.name`).
3. Берёт самое свежее событие, которое в этом городе ещё не рассказывали, если оно «дошло»: возраст ≥ `MIN_DELAY_DAYS` (K = 2) + расстояние / `DIST_PER_EXTRA_DAY` (+1 день на каждые 50 000 ед.) и не старше `MAX_AGE_DAYS`. Расстояние считается от персонажа игрока до места события по таблице `scripts\kmm_rumors_towns.lua` (169 городов из ванильного townlist, сгенерирована `tools\gen_towns.py`).
4. Искажает событие по уровню рассказчика:
   - 0 — бармен или торговец: точно, с именами;
   - 1 — по умолчанию и стража: без имени лидера («some big shot») и с оговоркой;
   - 2 — бандит, бродяга, раб: место события заменено направлением («somewhere far to the east»), с шансом 30% исход перепутан;
   - дальше `FAR_DISTANCE` (150 000 ед.) — уровень на 1 выше.
5. Доставляет:
   - реплика над головой NPC: `speaker:say(text)`;
   - дубль в журнал сообщений: `getGameWorld():showPlayerAMessage_withLog("Rumour (Имя): …", true)`.
6. Записывает, что уже рассказано: `C:\KenshiModMap\logs\rumors_told.tsv` (ключ `event_id|город`). Пишет свой лог `C:\KenshiModMap\logs\rumors.log` и `print()` в `KenshiLua.log`. Не больше 1 слуха за проверку и 1 на город за `TOWN_COOLDOWN_HOURS` (8 игровых часов).
7. Строки `event_type = materialized` новым событием не считает: это подтверждение от A.

## Что подтверждено, а что нет
| Механизм | Статус | Основание |
|---|---|---|
| Тик `Events.on("GameWorld::charsUpdate")`, троттлинг через `os.clock` | работает | скрипты CoK (8 подписок), запуск в тесте 21:29 подтверждён `KenshiLua.log` |
| Игровое время `getGameWorld():getTimeStamp_inGameHours():getTotalHours()` | работает (getTotalDays — в CoK; getTotalHours — тот же класс `TimeOfDay`) | GrowthManager.lua:563, BindingsReference `TimeOfDay` |
| `Character:say(text)` — реплика NPC | работает | CKBloodlines.lua:2837/3087/4255 (`TestSay … look for the speech bubble`) |
| `io.open` чтение и дозапись по абсолютному пути | работает | CoK/Bloodlines создают и читают конфиги через `io.open` |
| `getPlayerInterface():getAllPlayerCharacters()` + `pairs` | работает | GrowthManager.lua:1375 |
| `GameWorld:getCharacterUpdateList()` (активные персонажи) + `for c in pairs(set)` | **не проверено** | по биндингам и ContainersReference |
| `Character:getCurrentTownLocation()`, `TownBase:getName()` | **не проверено** | по биндингам; если `getName` недоступен — ключ города по координатам |
| `GameWorld:showPlayerAMessage_withLog(msg, queued)` — журнал сообщений | **не проверено** | по биндингам (`GameWorld`) |
| `Vector3` из `getPosition()` как таблица `{x,y,z}` | **не проверено** | `CallbacksReference` (`vector3Table`); код читает и `v.x`, и `v[1]` |
| Кириллица в пузыре реплики | **не проверено** | поэтому `LANG = "en"` по умолчанию, `"ru"` — переключатель |
| Направление «север = −z» | **не проверено** | если направления выходят наоборот — поменять знак в `direction()` |

Синтаксис Lua проверен своим токенизатором `tools\check_lua.py` (баланс блоков, скобок, строк); на рабочих скриптах CoK/Bloodlines он даёт OK. Интерпретатора Lua в системе нет, поэтому настоящего прогона не было.

## Варианты, которые не вошли в v0
- **Слух в диалоге бармена (ветка «Что нового?»)** через `DialogueScriptingBridge`: нужна запись `LUA_SCRIPT` (тип 322, поле `file`) и ссылка `run lua script` в `DIALOGUE_LINE` пакета бармена — это данные в `.mod`. kmod умеет писать тип 322 напрямую, без FCS Extended. Но Lua-моду генератор кладёт пустой `.mod`, а пакеты диалогов барменов — существующие записи, у которых по DECISIONS нет владельца. Значит, нужен шаг интегратора. Подставит ли скрипт свой текст в реплику (`DialogLineData.texts` / `Dialogue:say(text, line)` во время `_doActions`), не проверено: скрипт моста выполняется на действиях реплики, а не до показа текста.
- **Модальное окно / MyGUI-панель «Хроника»:** биндинги MyGUI и `lib/mygui/layout.lua` есть (так сделаны вкладки Bloodlines), но в v0 не делал — это уже не слух, а сводка «всезнающего» игрока, против DESIGN.md.
- **Сохранение «рассказано» внутри сейва:** API сохранения состояния мода в сейв в доке не нашёл. Сейчас `rumors_told.tsv` один на все сейвы: после загрузки старого сейва уже рассказанные слухи не повторятся.

## Ручной тест (на копии сейва `24days_KMMTEST`)
1. Интегратор ставит `build\KMM_Rumors\` → `Kenshi\mods\KMM_Rumors\` и добавляет `KMM_Rumors.mod` в mods.cfg.
2. Если A ещё не пишет хронику — скопировать `build\KMM_Rumors\test\chronicle_sample.log` → `C:\KenshiModMap\logs\chronicle.log`. Там 3 события «день 1»: Bark ×2, Blister Hill.
3. Загрузить сейв, привести персонажа в любой город к NPC (лучше в бар). Через ≤ 10 с:
   - над NPC реплика вида «Word is Lady Sanda was killed at Bark…» (точность зависит от рассказчика);
   - в журнале сообщений — «Rumour (Имя): …»;
   - в `C:\KenshiModMap\logs\rumors.log` — строка `told event=T1 town=… say=ok`.
4. Консоль KenshiLua (Ctrl+Shift+L): `print(KMM_Rumors.status())`; `print(KMM_Rumors.test("hello"))` — должен ответить `said by <имя>` и показать реплику.
5. В том же городе следующий слух — не раньше чем через 8 игровых часов. В другом городе слухи идут заново. Если будет `say=<ошибка>` или `tick error` в `rumors.log` / `KenshiLua.log` — прислать этот лог.

## Чего нет в движке / API
Записать слух в штатную систему диалогов и слухов NPC без правки данных диалогов нельзя: в биндингах нет API «добавить реплику в пакет» во время игры.

## v3 (2026-11-12): слухи о живом мире
- Шаблоны EN и RU для новых событий дирижёра v1: рейд, захват города, мобилизация и отход реликтовых, договор заключён или расторгнут, предательство, помощь союзнику или отказ, падение, подъём и упадок фракции.
- Искажение по роли. Бармен и торговец рассказывают точно. Бандит или бродяга (уровень ≥ 2):
  - с шансом 30 % путает исход: договор → предательство, мобилизация → рейд, помощь → отказ, упадок → падение;
  - в половине случаев не знает, кто именно это был («someone»).
- События без города (договоры, мобилизации) рассказываются с минимальной задержкой K дней.
